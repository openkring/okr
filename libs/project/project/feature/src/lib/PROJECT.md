# Project Domain

## Overview

A project groups tasks under a name, dates, a state and a project manager, and is a cost object
for the ledger (spec 3.14). It is deliberately not a project-management system: no milestones, no
dependencies, no Gantt. Tasks belong to a project through `TaskModel.parentKey = 'project.<okey>'`;
an empty `parentKey` is the backlog.

The feature is staff-only in the UI: the `/projects` routes carry `isPrivilegedGuard`.

## Firestore Collection

Collection name: `projects`

Access (decision R2): read tenant-wide, create/update/delete only for privileged users. Hiding the
menu row and guarding the route is navigation hiding, not privacy; the documents themselves are
readable by every member of the tenant.

## Field Semantics

| Field | Type | Description |
|---|---|---|
| `okey` | string | Firestore document ID (stripped on write, re-attached on read) |
| `tenants` | string[] | Multi-tenancy isolation; queries always filter by tenantId |
| `isArchived` | boolean | Soft-delete flag (set by `FirestoreService.deleteModel` when the last tenant is detached) |
| `name` | string | Project title |
| `index` | string | Computed search index (generated by `getProjectIndex`) |
| `tags` | string | Comma-separated tag list |
| `notes` | string | Free-text notes |
| `description` | string | What the project is about |
| `startDate` | string | `YYYYMMDD`; the anchor for the date shift when duplicating |
| `endDate` | string | `YYYYMMDD`; must not lie before `startDate` |
| `projectManager` | AvatarInfo? | Person who leads the project |
| `state` | string | Item of the `project_state` category: `planned`, `active`, `completed`, `cancelled` |

## Store

`ProjectStore` (component-provided on the list and on the page): filters `searchTerm`, `selectedTag`,
`selectedState`; `projectsResource` (non-archived, `ProjectService.list()`), `projectResource` (one
project, archived included, for the detail page). Methods:

- `add()` / `edit(p)` open `ProjectEditModal` (ui lib, inputs only, imported dynamically) and create or update on `confirm`.
- `delete(p)` asks for confirmation; the service moves the project's tasks back to the backlog first.
- `duplicate(p)` asks for confirmation, lets the user set name and new start date in the edit modal, creates the project and then its open tasks one after the other with due dates shifted by the start-date difference (`duplicateProjectTasks`). It shows a toast with the number of copied tasks and opens the new project.

## Components

- `ProjectList` (`okr-project-list`, inputs `listId`, `contextMenuName`): header count, search/tag/state filter, rows with manager avatar, dates and state chip, ActionSheet (open, edit, duplicate, delete).
- `ProjectPage` (`okr-project-page`, route input `projectKey`): header with name and edit button, segment «Aufgaben» with the project's `okr-task-list` (list and board).
